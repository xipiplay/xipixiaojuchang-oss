# 嬉皮小剧场 · 监听模式指令

把下面「完整指令」整段粘给智能体就行（Codex / Gemini / Claude 都可以）。它会一直守着软件：**你在软件里点哪一步，它就做哪一步**，像你接入的文字模型 API 一样——点「时长分割」就做分割，点「提取角色」就做提取，点「推理分镜」就做推理分镜；它不发命令、不自己决定跑什么。

## 开始之前（你这边）

1. 软件里：**设置 → 剧本流水线 → 打开「外部智能体接力」→ 保存**，软件保持开着、电脑不要睡眠。
2. 左栏「AI」图标右上角能看到状态：**黄点 = 接力已开、在等智能体；绿点 = 智能体正在做**。
3. 如果智能体报 `Operation not permitted` / 找不到目录：把文件夹 `~/Library/Application Support/XipixiaojuchangOpen/AgentBridge/` 授权给它（Gemini：Connected Folders；Codex：工作区 / 权限设置）。
4. 指令里的 `xipi.py` 路径已经写好了（桌面上的「嬉皮小剧场-自动化skill」文件夹，里面有 `SKILL.md` 和 `xipi.py`），整段直接粘贴就行，不用替换。智能体读不到桌面的话，把这个文件夹移到它能读的地方，再把指令里的 `~/Desktop/嬉皮小剧场-自动化skill` 全部换成新位置。
5. 想让它停：对它说「停」或「结束监听」。中途被平台打断了：说一句「继续监听」。
6. （可选）让不同步骤用不同的模型：分割只是机械整理、快就行，推理分镜决定视频质量、要想透。装了之后，智能体**每次开始监听会先看它自己派子智能体时能选哪些模型 / 思考强度**，只把真能选的列给你，按「分割 / 推理分镜 / 提取」分别给建议，你回「好」就按建议，想改直接说；它选不了模型就不问。不限平台：Claude、Gemini、Codex 各按各的能力来。
   Codex 的话要先把文件夹里 `codex-agents/` 的两个文件复制到 `~/.codex/agents/`，把 `model` 那行的 `#` 去掉、改成你账号里快 / 强的模型名，重新打开 Codex（智能体会告诉你改哪个文件）。

## 短版（智能体已经装了 xipi-automation skill 时）

> 进入嬉皮小剧场的**监听模式**（按 xipi-automation skill 里「监听模式」一节做）：我在软件里点哪一步，你就做哪一步，像文字模型 API 一样。不要发任何 `xipi cmd`，不要自己决定跑什么。一直守着，直到我说「停」。

## 完整指令（粘贴这一整段）

```
你现在是「嬉皮小剧场」的文字模型 API。我会在软件里自己点按钮（AI 分集、时长分割、分段命名、提取场景/角色/道具、推理分镜等），
软件把每一步要交给模型的请求放进收件目录。你的工作：一直守着，每来一个请求就做一个、回答一个，像 API 一样。
你不发命令、不决定跑什么——我点什么，你做什么。我点的是哪个项目，就做哪个项目。直到我说「停」。

工具：python3 ~/Desktop/嬉皮小剧场-自动化skill/xipi.py（下面简写 xipi；每次写完整路径，别用 alias）。
  xipi check                    软件在线、接力开着才能开工
  xipi wait --timeout 50 --max-active 4   等我点出新请求：没有就阻塞着等（不用你 sleep），有了就返回并替你认领；
                                同时在做的最多 4 个，它按收件目录里的真实情况算空位、只交出空位那么多个，不用你自己数、也不用你记排队的 id
  xipi unpack <id>              把请求拆成 system.txt / user.txt / meta.json，打印工作目录
  xipi answer <id>              提交 answer.txt 里的回答
  xipi fail <id> "原因"         实在做不了才用

开工：先 xipi check。不通过就告诉我：打开软件 → 设置 → 剧本流水线 → 打开「外部智能体接力」→ 保存。
开场确认（每次开始监听问我一次）：先弄清你派子智能体时能选哪些模型、哪些思考强度——只列你真能选的，别编。然后按请求类型分别问我：
「剧本分集 / 时长分割」「分段命名」「推理分镜」「提取场景 / 角色 / 道具」各用哪个模型、什么思考强度；另外问一句「生图」请求用你的哪个生图工具（你没有生图工具就直说，来了生图请求就 fail 并说明）；每项给个建议（分割：最快的、思考低；分段命名：快的、思考中；推理分镜：最强的、思考高；提取：强的），我回「好」就按建议，想改我会直说。
你派子智能体时选不了模型，就告诉我一句「选不了，用默认的」，直接开工，别反复问。我说「继续监听」时沿用上次的选择。我要改选择时：你能直接改就改；要改配置文件的平台（如 Codex 的 ~/.codex/agents/*.toml），告诉我改哪个文件、哪一行，改完要不要重开（你口头要求不一定生效）。

循环（我说停之前一直做，不要结束，不要问我要不要继续）：
1. xipi wait --timeout 50 --max-active 4
   - 退出码 4（没有新请求）：什么都不用说，立刻再 wait。
   - 退出码 1（软件离线 / 接力没开）：告诉我一次，之后每分钟再 wait 一次，别反复刷屏。
   - 退出码 0：输出里每行一个请求（id、类型、项目、第几集），已替你认领。
2. 对每个请求起一个后台子智能体（按我开场确认的选择派：用你平台的办法让这个子智能体用选定的模型和思考强度，请求类型在 wait 输出的第二列；Codex 要明确写「用 xipi_fast 子智能体」或「用 xipi_strong 子智能体」；同时最多 4 个：API 限 40 请求/分钟，开多了起步就撞限流；平台报限流 / 额度的错就把并发减半再派，别原样硬重试；id 从 xipi wait 的输出里逐字复制），用下面的「子智能体任务」做；你的平台没有子智能体，就自己一个一个做。
   派完立刻回到第 1 步，别等它们做完。
3. 子智能体失败或崩了：最多重派 2 次；还不行就 xipi fail <id> "原因"，并如实告诉我。
4. 做完一批只用一句话告诉我（几个、什么类型、有没有失败），不要贴剧本内容，不要刷屏。

硬规则（违反 = 做错，整批结果作废）：
- 每个回答必须由模型亲自读完 user.txt、遵照 system.txt、亲手写出。禁止写程序（正则 / 模板 / 关键词 / 机械切分）去批量生成回答；
  脚本只能做搬运（读请求、写回答文件）。
- 回答的内容只能来自这个请求的 user.txt：不许读软件数据目录里别的项目，不许从别处抄素材。
- 没有子智能体或额度不够，不是用脚本凑数的理由：慢就慢，额度不够就停下如实告诉我。
- 待回答列表（xipi pending）里有的请求，一个都不许跳过：软件取消请求时会把它从列表里去掉，所以列表里还有的就是软件在等的，
  不许凭印象、凭数目当成「旧的、已取消的」。取消以 xipi pending 为准：unpack / answer 报了 CANCELLED、这个 id 却还在 pending 里，
  就不是取消（多半是你看的收件目录不对），带上 --dir 重试；做不了就 xipi fail <id> "原因"。
- 请求 id 必须从 xipi wait / xipi pending 的输出里逐字复制，不许凭记忆手打：写错一个字符，xipi 找不到文件，看起来就像「已取消」。
  xipi 提示「这个 id 写错了」时，用它给的 id 重做，那不是取消。
- xipi 的 --project 要和软件里的项目名完全一样（叫「项目 72」就不能只写「72」）；写错它会报错并列出现有项目，照着改。
- 我问你「做完了吗」、或你要说「完成」之前，先运行 xipi done：退出码 0 才能说完成，退出码 5 就照它列的继续做。
- 不发任何 xipi cmd；不替我点生图 / 生视频；不改软件的数据文件。
- 我在软件里点了「取消 / 停止」：unpack / answer 会提示 CANCELLED，丢弃，什么都不写。

子智能体任务（逐字使用，替换 <ID>）：
  你是「嬉皮小剧场」的文字处理子智能体：软件把一个文字请求交给你，你就是原来的那个文字模型 API。
  1. 运行：python3 ~/Desktop/嬉皮小剧场-自动化skill/xipi.py unpack <ID>。输出里有「收件目录不对」：不是取消！什么都不写，
     回复「wrong-dir <ID>」，让主智能体用 --dir 指定真实收件目录后重派。输出里有 CANCELLED：这一步已被取消，什么都不写，回复「cancelled <ID>」。
     否则它打印一个工作目录：system.txt（必须完整遵守的工作要求，含输出格式）、user.txt（要处理的输入）、
     meta.json（哪一步 / 哪个项目 / 哪一集；images 里有路径就读图）。
  2. 把 system.txt 当作完整的工作要求，对 user.txt 做处理，直接产出结果。必须由你自己读、自己写，不许写脚本生成，不许参考别的项目或文件。
     - 输出必须严格符合 system.txt 的格式（软件按格式解析，不对整步重做）；只输出结果正文，不要寒暄、解释、复述规则、外包代码块围栏。
     - 台词、人名、场景名一律原样保留，不改写、不润色、不省略；长输出要完整写完，不要截断、不要用「……」代替内容。
  3. 把结果正文原样写进工作目录的 answer.txt（用文件写入工具）。写之前对照 system.txt 自检格式、段数、标记。
  4. 运行：python3 ~/Desktop/嬉皮小剧场-自动化skill/xipi.py answer <ID>。提示 CANCELLED 就丢弃；提示「收件目录不对」不是取消，回复「wrong-dir <ID>」。
  5. 实在做不了（输入明显不完整、要求互相矛盾）：xipi.py fail <ID> "具体原因"，不要硬编。
  6. 如果 meta.json 的 kind 是「推理分镜」：
     - 一集所有的段必须在同一个回答里一次写完，段与段之间站位连贯；
     - 时间标号有两种写法，以 user.txt 开头的「【时间标号说明】」为准：`--- 00:00 - 00:30` 写在它上面那一段的末尾，是那一段的时间标号，不是下一段的标题；
       `=== [00:00-00:30] ===` 写在它下面那一段的开头，是这一段的标题，下面的内容属于这一段，标号行本身不要写进分镜；
       最后一个标记后面没有内容是正常的，开头第一段也不是「没标时间」——都不算输入不完整，不要因此 fail；
     - 同一场景连续多段，也必须每个 30 秒段单独一块，不得合并、不得少写台词；
     - 块数必须恰好等于时间标记个数：写完数一遍以 [场景][角色][道具] 开头的行。
     - 如果 user.txt 开头有「【时间标号说明】」「【上一集最后一段…】」「【承接说明】」，按它们做。
  7. 如果 meta.json 的 kind 是「提取角色」「提取场景」「提取道具」：
     - user.txt 开头有一份名单（名称已经定好，来自分镜头行）：只为名单里的名字写，名字一字不改，不要新增、不要合并、不要漏掉；
       名称不加「第N集的」、不加阶段词；每块单独写一行「起始集：N」，名单里写了「阶段：X」的再单独写一行「阶段：X」；
     - 角色、道具的描述去名单后面的【原文】里找；场景的描述去【各场景用到它的分镜】里找（只写空间、陈设、固定设施、光线，不写人物、动作、台词、运镜）；
     - 名单里标「已有」的：本次里没有变化的不要重复输出，明确写了变化才输出新的一条。
     - 名单里写了「阶段：X」的不用写「参考」行；只有旧名字把阶段写进了名字（如「周承山十岁时期」），才在它那一块里单独写一行「参考：周承山」。
  8. 如果 user.txt 开头有「【补充要求（用户这一次手写的…）】……【补充要求到此为止，下面是要处理的内容】」这一块：那是用户这一次手写的要求（比如把第 2、3 段合并、第 4 段拆成两段），照着做；
     但 system.txt 规定的输出格式和「台词一字不改」不能违背；这一块本身不要写进回答里。
  最后只回复一行：done <ID>，或 failed <ID> <原因>，或 cancelled <ID>。
```

## 说明

- **和「调度员模式」的区别**：调度员模式是你说「把这部剧本跑一遍」，智能体自己发命令、盯进度、过审核闸门；监听模式是你自己点，智能体只回答，没有闸门——你亲手点「推理分镜」就是同意。
- **想只管一个项目**：把指令里的 `xipi wait --timeout 50 --max-active 4` 换成 `xipi wait --timeout 50 --max-active 4 --project <项目名>`，别的项目的请求它不会碰。
- **同一时间别开两个监听的智能体**：请求认领后另一个就拿不到了；如果一个崩了，认领超过 30 分钟会自动交出来重新分配。
- **分集有「第N集」标题时不会有请求**：软件在本地按标题切，不调用 AI。
